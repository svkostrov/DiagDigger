# DiagDigger — предложения по группировке категорий

Выписка из раздела «Аудит 4» файла `bugreport.md` (строки 2366–2490) — отдельным файлом для удобства чтения. Единственный источник истины остаётся в `bugreport.md`; правки вносить туда.

Статус на 1 сентября 2026: совместимые рекомендации реализованы в версии 2.1.
По прямому требованию пользователя IPv6 сохранён отдельной категорией в группе
«Сетевые правила». JSON-таблица покрыта синтетическим тестом, сообщение пустого
массива упрощено, `show ip arp` и `show ip neighbour` объединены в «Списках
клиентов». Подробности проверки записаны в `bugfixed.md`.

## Предложения по группировке категорий

Сверено с тремя источниками: живой веб-конфигуратор (Keenetic Ultra, версия ОС 5.0,
меню прочитано целиком), документация Netcraze для Ultra NC-1812 и справочник команд
`tmp/pdfs/cli_manual_nc-1812.pdf` (редакция 1.169 от 29.07.2026).

Меню веб-конфигуратора — пять групп и 24 страницы:

| Группа | Страницы |
| --- | --- |
| Статус | Системный монитор · Монитор трафика · Анализатор трафика приложений · Монитор Wi-Fi |
| Интернет | Кабель Ethernet · Wireless ISP · Другие подключения · Приоритеты подключений |
| Мои сети и Wi-Fi | Списки клиентов · Точки доступа · Сегменты · Wi-Fi-система · IntelliQoS |
| Сетевые правила | Интернет-фильтры · Межсетевой экран · Переадресация портов · Маршрутизация · Доменное имя · Контроль доступа Wi-Fi |
| Управление | Настройки системы · Накопители и устройства · Приложения · Пользователи и доступ · Диагностика |

Пять групп `NAV_GROUPS` в приложении названы так же и идут в том же порядке — это
уже хорошо и менять не надо. Расхождения — внутри групп.

**1. Перенести «QoS» в «Мои сети и Wi-Fi» и назвать «IntelliQoS».** В роутере
IntelliQoS — пункт «Моих сетей и Wi-Fi», не «Сетевых правил». Название «QoS» в
интерфейсе роутера и в документации не используется.

**2. Перенести «Доменное имя» в «Сетевые правила» и объединить с «Облаком».** В
роутере «Доменное имя» (`/remoteAccess`) — пункт «Сетевых правил» и включает KeenDNS,
NDNS, удалённый доступ. Сейчас в приложении `domain` лежит в «Управлении», а `cloud`
— в «Сетевых правилах», при том что это один предмет. Предлагаю одну категорию
«Доменное имя и удалённый доступ» в «Сетевых правилах»: `ndns`, `ndss`, `cloud`,
`oc-server`, `dyndns`, `show cloud ndmp *`.

**3. Убрать отдельную категорию «IPv6».** В роутере отдельного пункта IPv6 нет:
настройки живут внутри подключений и сегментов, в документации Netcraze IPv6 —
подраздел «Интернета». Предлагаю распустить `ipv6` по `internet` (адреса, префиксы,
`ipv6 pass`) и `routing` (`ipv6 route`, `ipv6 static`), либо, если разбивать не
хочется, перенести категорию целиком в группу «Интернет».

**4. Назвать «Хосты» → «Списки клиентов» и собрать в неё все таблицы устройств.**
Сейчас `show device-list` и `show ip neighbour` → «Хосты», а `show ip arp` →
«Сетевые правила». ARP-таблица — это список клиентов, в «Сетевых правилах» роутера
её нет. Перенести `show ip arp`, `known host`, `ip dhcp host` в «Списки клиентов».

**5. Разобрать категорию «Безопасность» — такого пункта в роутере нет.** Сейчас в
ней смешаны межсетевой экран, права пользователей и доступ по протоколам управления.
Предлагаю три категории вместо одной:
- «Межсетевой экран» в «Сетевых правилах»: `access-list`, `firewall`,
  `object-group ip`, `isolate-private`, `show netfilter`, `show ip rule`;
- «Пользователи и доступ» в «Управлении»: `user`, `ip ssh`, `ip telnet`, `ip http`,
  `ip ftp`, `show ssh fingerprint`, `show authentication session`,
  `show ip http lockout-policy`, `show ip telnet lockout-policy`,
  `show ip http config-errors`;
- «Контроль доступа Wi-Fi» в «Сетевых правилах»: списки доступа точек доступа,
  `mws member port access`.
Это заодно закрывает половину BUG-087.

**6. Переименовать «Сетевые правила» (категорию) в «Переадресация портов».**
Категория с тем же именем, что и группа, — путаница: группа «Сетевые правила»
содержит категорию «Сетевые правила». В роутере на этом месте «Переадресация
портов». Оставить в ней `ip nat`, `ip static`, `ip static rule`, `upnp redirect`;
`dyndns` перенести в «Доменное имя» (пункт 2), `object-group fqdn` — в
«Интернет-фильтры» (пункт 7).

**7. Добавить категорию «Интернет-фильтры» в «Сетевые правила».** В роутере это
первый пункт группы. Сейчас `dns-proxy filter`, `nextdns`, `skydns`,
`object-group fqdn` либо попадают в «DHCP и DNS», либо теряются в «Прочем».
Выделить фильтрацию из `dhcp`, оставив в «DHCP и DNS» пулы, привязки, резолверы и
`ip name-server`.

**8. Добавить «Анализатор трафика приложений» в «Статус».** В роутере это отдельный
пункт. Данные уже есть: `show ntce applications`, `attributes`, `groups`,
`groupsets`, `oses`, `hosts`, `status`, `filter profile` — сегодня шесть из восьми в
«Прочем» (BUG-087).

**9. Добавить категорию «Телефония».** Справочник NC-1812 содержит отдельный
раздел NVOX и 15 команд `show nvox *`; документация Netcraze выносит «Телефонную
станцию» на верхний уровень. В приложении такой категории нет, поэтому вся телефония
попадает в «Прочее». Минимум — одна категория `telephony`; полнее — «Линии SIP»,
«Журнал звонков», «Телефонные аппараты». На проверенном Keenetic Ultra пункта
телефонии в меню нет (компонент не установлен), так что показывать категорию стоит
только когда данные есть, — приложение уже так делает для всех категорий.

**10. Назвать «USB» → «Накопители и устройства», «Логи» → «Диагностика»,
«Общие настройки» → «Настройки системы», «MWS» → «Wi-Fi-система», «Wi‑Fi» →
«Точки доступа», «Интерфейсы» → «Сегменты».** Все шесть — названия пунктов роутера;
текущие названия либо внутренние (MWS, USB), либо не совпадают с тем, что
пользователь видел в веб-конфигураторе, откуда он скачал self-test.

**11. Перенести «Оборудование», «Процессы и ядро», «Память» из «Статуса» в
«Диагностику».** В роутере «Статус» — это Системный монитор, Монитор трафика,
Анализатор трафика приложений и Монитор Wi-Fi, то есть то, что показывают
пользователю. `proc:`, `sys:`, `meminfo`, `slabinfo`, `interrupts` — внутренняя
диагностика, и в роутере она доступна только через файл диагностики. Предлагаю
«Статус» = Системный монитор (`show system`, `show version`, `show defaults`,
`show identification`, температуры) + Монитор трафика (`show interface stat`,
`rrd`, `traffic-counter`) + Анализатор трафика приложений + Монитор Wi-Fi
(`show associations`, `show interface channel-utilization rrd`); остальное — в
«Управление → Диагностика».

**12. Отнести мобильные и DSL-подключения к «Интернету», а не к «Интерфейсам».**
`show interface cells`, `show interface operators`, `show interface esim status`,
`show interface dsl*` сейчас уходят в «Интерфейсы» по слову `interface`. В роутере и
документации это «Интернет» (мобильные подключения, Wireless ISP).

**13. Заменить эвристику `showCategory` таблицей по префиксу команды.** Корень
BUG-087: категория определяется вхождением слова в строку, порядок правил значим,
`policy` перехватывает `lockout-policy`. Словарь команд конечен и опубликован —
оглавление справочника даёт полный список. Предлагаю таблицу «самый длинный
совпадающий префикс → категория», собранную из оглавления, с эвристикой только как
последним резервом, и тест, который сверяет покрытие таблицы со списком команд из
справочника. Тогда рост словаря в новой прошивке будет виден как падение теста, а не
как тихий рост раздела «Прочее».

Три предложения не про группировку, но замечены попутно:

- **Ветка JSON-таблицы (`renderJsonTable`) не задействуется ни на одной из восьми
  реальных диагностик.** Все JSON-секции фикстур — объекты и массивы строк;
  массива объектов, для которого написана таблица, нет ни в одной. Код отгружен без
  проверки реальными данными. Стоит либо найти диагностику, где такой массив есть,
  либо добавить синтетическую фикстуру.
- **Пустой массив показывается как «0 значений · Пустой массив».** Формулировка
  верная (проверено: `subscription.event` в `temp:coalagent.conf` — именно массив),
  но два сообщения об одном и том же дублируют друг друга.
- **`show ip arp` и `show ip neighbour` разведены по разным категориям** — см.
  пункт 4; это единственная пара, где два взгляда на одну таблицу оказались в
  разных разделах.
