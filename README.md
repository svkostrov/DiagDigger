# DiagDigger

Локальный web-инструмент для просмотра и смыслового сравнения self-test файлов роутеров и ретрансляторов Keenetic/Netcraze.

Диагностики разбираются только в браузере: содержимое файлов не отправляется на сервер и не сохраняется приложением.

## Быстрый запуск в Docker

Нужны Docker Engine и Docker Compose v2.

```bash
git clone https://github.com/svkostrov/DiagDigger.git
cd DiagDigger
docker compose up -d --build
```

Откройте [http://localhost:4173](http://localhost:4173). Остановка контейнера:

```bash
docker compose down
```

Чтобы запустить образ без Compose:

```bash
docker build -t diagdigger .
docker run --rm -p 4173:80 diagdigger
```

## Локальная разработка

Требуется Node.js (для тестов). Зависимости для обычного просмотра не нужны.

```bash
npm install
npm run dev
```

Откройте `http://localhost:4173`, затем добавьте один или несколько `.txt` self-test файлов.

Можно выбрать несколько файлов сразу. Во время разбора отображается текущий файл; повторные одинаковые диагностики не добавляются.

## Возможности

- адаптивная группировка исходных секций диагностики;
- дополнительное разбиение конфигурации на Wi‑Fi, туннели, интерфейсы, маршрутизацию и сервисы;
- полнотекстовый поиск (⌘K / Ctrl+K), возврат к найденным результатам;
- быстрый переход к разделу по названию, в том числе на телефоне;
- компактная сводка и раскрываемые сведения о сборке;
- дата диагностики в выборе файлов и копирование секций через локальный HTTP;
- сравнение секций с поддержкой данных, присутствующих только в одном файле;
- смысловое сравнение диапазонов Wi‑Fi, PPPoE-подключений, WireGuard и других VPN-туннелей;
- исходные неизвестные секции всегда сохраняются в категории «Прочее».

## Устройство Docker-версии

Контейнер содержит только Nginx и статические файлы приложения. Он не получает
self-test файлы: браузер читает выбранные пользователем данные через File API.
Порт контейнера `80` опубликован на `4173` хоста в `compose.yaml`; при
необходимости измените левую часть значения `4173:80`.

## Тесты

```bash
npm test          # юнит-тесты парсера (node:test), без зависимостей
npm run test:ui   # e2e-тесты интерфейса (Playwright, Chromium)
npm run test:all  # и то и другое
```

Перед первым прогоном e2e:

```bash
npm install
npx playwright install chromium
```

`npm run test:ui` сам поднимает `python3 -m http.server 4173`. Если браузер
уже установлен в другом месте, путь к нему можно передать через
`PW_CHROMIUM_PATH=/путь/к/chrome npm run test:ui`.

Тестовые диагностики хранятся локально в `tests/fixtures/` и исключены из Git.
Если папка отсутствует, зависящие от неё тесты пропускаются. Локальный набор —
восемь реальных self-test
(KN‑1811, KN‑1912 ×2, KN‑1621, KN‑1713, KN‑2110, KN‑3013, NC‑1812), включая
роутеры и ретранслятор, каналы stable/testing/nightly, файл на 6,9 МБ,
устройство с несброшенными часами (1970) и файл, не являющийся валидным XML.

Тесты, помеченные `skip` с номером `BUG-xxx`, описывают ожидаемое поведение и
отключены до исправления дефекта. Рядом с каждым лежит тест
`BUG-xxx воспроизводится`, фиксирующий текущее фактическое поведение: если
дефект будет исправлен, этот тест упадёт и напомнит снять `skip` и обновить
локальную документацию о дефектах.

## OMV и проверка публикации

Если весь каталог проекта смонтирован в Nginx, worker должен иметь право прохода
в корневой каталог и чтения публичных файлов. При 403 проверьте `docker logs diagdigger` и права каталога. Не меняйте права
рекурсивно для конфигураций и приватных файлов. Nginx публикует только файлы
приложения, перечисленные в `nginx.conf`; остальные URL возвращают 404.

После изменения конфигурации: `docker exec diagdigger nginx -t`, затем
`docker exec diagdigger nginx -s reload`. Проверьте 200 для `/`, `/app.js`,
`/parser.js` и CSS, 404 для `/.git/config`, `/compose.yaml`, `/tests/fixtures/`.
`Cache-Control: no-cache` разрешает браузеру хранить файлы, но требует
перепроверять их актуальность при обращении к серверу. Если отдельно смонтированный
`nginx.conf` заменён с изменением inode, потребуется `docker restart diagdigger`
и повторная проверка: reload может продолжать читать старый файл.

План и результаты текущего улучшения: [REFACTORING_PLAN.md](REFACTORING_PLAN.md).
Быстрая проверка новых сценариев:

```bash
npx playwright test tests/usability-current.spec.js tests/version-current.spec.js
```

Тест новой диагностики пропускается, если её нет в локальной `tests/fixtures/`.
